## 切换顺序

1. 在新机将 `/etc/systemd/system/capability-advisor.service.d/loopback-preview.conf` 重命名为同目录的 `.disabled` 文件，再执行 `systemctl daemon-reload`、重启应用并检查 `/health`。确认回环预览 Host 不再被接受，正式 `Host: surfacedmp.com` 可到达健康接口。
2. 确认 `/etc/caddy/Caddyfile` 与仓库 `deploy/Caddyfile` 相同且语法有效；启用并启动 Caddy。此时域名仍指向旧机，证书申请可能暂时失败，不应把此阶段当作 HTTPS 验收。
3. 将两个 A 记录都改为 `123.207.183.23`，不要修改任何 `yiheit.net` 记录。观察 Caddy 日志，等待根域名和 `www` 的受信任证书签发。
4. 从独立外网验证 `https://surfacedmp.com/health` 返回 200、证书域名与有效期正确、`http://` 自动升级 HTTPS、`https://www.surfacedmp.com/` 跳转到根域名；核对安全头。不要使用 `-k` 或忽略浏览器证书警告作为验收。
5. 以测试用户验收登录、受保护顾问与 PDF；未登录/过期 License 路径保持拒绝。检查 SMTP、备份状态和应用/Caddy 错误日志，记录时间与结果；不得记录密码、令牌或 MFA 种子。

## 回退触发与动作

如果 DNS 生效后约 10 分钟仍无法取得有效证书，或出现登录保护失效、关键业务失败、数据库异常：立即将两个 A 记录恢复到切换前记录的旧 IP，核实旧站重新可达。新机保持隔离，不清除数据库或备份；收集已脱敏日志分析原因。DNS 缓存可能使部分访问者在一个或多个 TTL 内继续到达新机，故新机的 HTTPS 服务和访问保护不要在回退时仓促关闭。恢复预览 override 仅用于受控排障，正式公网状态不得与预览开关并存。

旧服务器上的宝塔证书私钥无需上传到聊天或仓库。Caddy 在 DNS 指向新机且 80/443 可达时申请与续期证书；如果此路径失败，先回退，另行选择安全的证书安装方式。
